# Schema in C++

[Reference](../../README.md#reference) · Concept: [Schema](../../explanation/concepts/schema.md) · TypeScript: [Schema in TypeScript](../typescript/schema.md)

Headers: the generated `schema.generated.hpp`, and `oly/app/schema.hpp` and `oly/app/game.hpp` for the two functions the build defines. The `.oly` file, its field types and its naming rules are in [The `.oly` schema language](../../../engine/schema/format/README.md). What the order of the entries means: [Order matters](../../explanation/concepts/schema.md#order-matters).

## The five kinds of entries

C++ gets every entry from the generated header:

```cpp
#include "schema.generated.hpp"
```

### `struct`

A component, a tag or an event becomes a struct with the name you wrote (`Health`, `Enemy`, `EnemyDied`). A tag is an empty struct. You pass the type to every API call: `context.get<Health>(entity)`, `context.emit(EnemyDied{...})`.

### `actions::<name>`

An action becomes a constant in the `actions` namespace, typed by its kind (`oly::input::ButtonAction`, `oly::input::Axis2dAction` or `oly::input::PointerAction`), with its index as the id: `context.actions().button(actions::shoot)`.

### `states::<name>`

A state becomes an `oly::app::StateId` constant in the `states` namespace, with its index as the id: `states::playing`.

## What the build generates

On every build, `oly-schema` reads the `.oly` file and writes the generated files of the game. They are never committed and never edited.

| File | Holds |
|---|---|
| `schema.generated.hpp` | the structs, `actions::` and `states::` |
| `schema_registry.generated.cpp` | the schema hash and the component ids, which the C API reads; only web targets compile it |
| `schema_declaration.generated.cpp` | `oly::app::declareSchema(Engine&)` |
| `game_setup.generated.cpp` | `oly::app::setUpGame(Engine&)`: `declareSchema`, then the install of each plugin |

### `schema.generated.hpp`

For the schema in [The five kinds of entries](../../explanation/concepts/schema.md#the-five-kinds-of-entries), this is an excerpt of the header:

```cpp
// Generated by oly-schema: do not edit.
// ...
struct Health { int32_t value; };
struct Target { oly::ecs::Entity entity; };
struct Enemy {};
struct EnemyDied { oly::ecs::Entity entity; float x; float y; };

namespace actions {
  inline constexpr oly::input::Axis2dAction move{0};
  inline constexpr oly::input::PointerAction aim{1};
  inline constexpr oly::input::ButtonAction shoot{2};
}

namespace states {
  inline constexpr oly::app::StateId menu{0};
  inline constexpr oly::app::StateId playing{1};
}
```

The real header writes each struct over several lines, follows it with `static_assert`s of its size, alignment and field offsets, and lists every component, tag and event. A type that comes from a plugin is not defined here: the header includes the plugin's own header.

### `oly::app::declareSchema`

```cpp
void declareSchema(Engine& engine);
```

Declares the schema's events, actions and states in schema order, so the index in the schema is the id. Stops with `OLY_ASSERT` (`declareSchema: the Engine already declares events, actions or states`) when the `Engine` already declares any of them.

### `oly::app::setUpGame`

```cpp
void setUpGame(Engine& engine);
```

Calls `declareSchema`, then installs the game's [plugins](../../explanation/concepts/plugins.md) in dependency order. Call it once per `Engine`, before the first frame:

```cpp
oly::app::setUpGame(engine);
```

Where you do not own the `Engine`, the host does this for you ([the web host](../typescript/README.md), [the desktop host](../native-host.md)).
